# Web analyzer

A browser front end for `nthunt`. It is published to GitHub Pages by
[`.github/workflows/pages.yml`](../.github/workflows/pages.yml).

## How it works

| File | Role |
|---|---|
| `index.html`, `styles.css`, `app.js` | The page: file drop, detector settings, findings tables, export |
| `engine-worker.js` | A Web Worker that loads Pyodide (Python in WebAssembly) and Scapy, so analysis never freezes the page |
| `engine.py` | Thin bridge. Imports `nthunt`, reads `COMMANDS` from `nthunt/cli.py`, loads the capture with `nthunt.pcap_loader.iter_packets`, and calls each detector exactly like the CLI does |
| `sw.js`, `manifest.webmanifest`, `icons/` | Make the page installable as an app and cache the ~15 MB Python runtime after the first visit |
| `samples/synthetic-lab.pcap` | A made-up 30-minute capture for demos and testing (see below) |

There is **no detection logic in the web code**. When a function in `nthunt/`
is implemented, the analyzer notices on the next deploy: its "Not built yet"
badge becomes "Ready", its keyword arguments (thresholds) become editable
settings, and whatever it returns is rendered automatically:

- a list of dicts becomes a sortable table (one row per finding)
- a dict becomes a set of sections: numbers and strings as headline stats, `Counter.most_common()` lists and nested dicts as tables
- anything else is shown as JSON

Every result can be downloaded as JSON or copied as a Markdown table (defanged
by default) for the *Toolkit Output* section of a case report. Timestamp
fields whose names contain `time`, `first`, `last`, `start`, `end` or `seen`
are shown as UTC dates.

## Demo link

Add `?demo` to the address (for example on a resume or LinkedIn) and the page
loads the sample capture and runs every built detector as soon as it opens.
The **See it in action** button does the same thing.

## Preview locally

From the repository root:

```bash
python -m http.server 8000
```

Then open http://localhost:8000/web/. The first load downloads Pyodide and
Scapy (about 15 MB). On later visits they come from the service worker's cache.

## Sample capture answer key

`samples/synthetic-lab.pcap` is generated by `samples/make_sample.py`
(fixed random seed, documentation/private IP space only, no real traffic).
Use it to check each detector as you build it:

| Activity | Source | Details |
|---|---|---|
| Normal browsing | 10.0.0.11, .12, .14, .23 | DNS + HTTPS to 198.51.100.0/24 at irregular intervals |
| Beaconing | 10.0.0.23 → 203.0.113.66:443 | 29 connections, every 60 s ± 1.5 s (after resolving `update-check.example.net`) |
| DGA-style lookups | 10.0.0.37 | 25 random 13–19 character `.com/.net/.info` names, mostly NXDOMAIN |
| DNS tunneling pattern | 10.0.0.37 | 30 queries with 52-character base32 labels under `exfil.example.org` |
| Vertical scan | 10.0.0.66 → 10.0.0.10 | SYN to ports 1–150 in 15 s; RST from closed ports, 6 open |
| Horizontal scan | 10.0.0.66 → 10.0.0.100–139 | SYN to port 445 on 40 hosts in 8 s |

## Limits

- Everything is held in browser memory. Captures up to roughly 150 MB work
  well; larger ones should be trimmed in Wireshark or run with the CLI.
- Scapy can only parse files here. Live capture and sending packets are not
  possible in a browser.
